1Чем POST принципиально отличается от GET и почему формы отправляют именно POST?
ответ: GET запрашивает данные с сервера, а все параметры передаются открыто прямо в адресной строке (URL). POSTотправляет данные на сервер внутри тела запроса — они скрыты из адресной строки, не имеют ограничений по объёму и не сохраняются в истории браузера. Формы отправляют через POST, чтобы данные (особенно пароли или длинные тексты) не светились в ссылке и не приводили к случайной повторной отправке.


2Что произойдёт, если убрать methods=['GET', 'POST'] из маршрута?
ответ:   По умолчанию Flask разрешает только метод GET. Если убрать этот параметр, то при попытке отправить форму (нажать кнопку «Добавить») сервер выдаст ошибку 405 Method Not Allowed (Метод не разрешен).


3 Зачем нужен паттерн Post/Redirect/Get? Что сломается без него?
ответ:    Он нужен для защиты от дублирования данных. Без него, если пользователь после добавления задачи нажмет кнопку Обновить (F5), браузер повторно отправит последние POST-данные формы, и в базе данных создастся еще одна точно такая же задача. Redirect переводит браузер в режим безопасного GET-просмотра.

4Почему url_for('index') лучше, чем жёсткая строка '/'?
ответ:  Это делает код гибким. Функция url_for находит адрес динамически по имени функции. Если вы позже решите изменить адрес главной страницы в декораторе (например, сделать /home вместо /), вам не придется вручную переписывать ссылки во всех HTML-файлах — Flask сам сгенерирует правильный URL.


5Почему request.form.get('title', '') безопаснее, чем request.form['title']?
ответ:   Метод .get() безопасен: если поля 'title' вдруг не окажется в запросе, он просто вернёт пустое значение по умолчанию (''). Прямое обращение через квадратные скобки ['title'] в таком случае вызовет критическую ошибку Python (KeyError), и сайт сломается.


6Зачем нужна серверная валидация, если в HTML уже есть required?
ответ:  Атрибут required работает только в браузере. Его легко обойти: злоумышленник может удалить этот атрибут через код страницы (DevTools F12) или отправить пустой запрос напрямую через скрипт. Проверка на сервере (if not title:) — это гарантированная защита базы данных от мусора.

7В каком порядке идут транзакции при добавлении задачи через форму?
ответ:  Порядок строго следующий:
1Открывается соединение с базой данных (get_connection()).
2Выполняется SQL-запрос на добавление (INSERT INTO...).
3Изменения окончательно фиксируются на жесткий диск (conn.commit()).
4Соединение закрывается (conn.close()).
