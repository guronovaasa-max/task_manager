1Почему для SELECT не нужен commit(), а для INSERT — нужен?
ответ: SELECT только читает данные из базы (ничего не меняя), поэтому сохранять нечего. А INSERT изменяет базу (добавляет новую строку), и чтобы эти изменения окончательно записались на диск, требуется команда фиксации — commit().

2Что вернёт fetchone(), если в таблице нет строк?
ответ: Он вернёт пустое значение — None.

3Чем fetchone() отличается от fetchall() и когда какой использовать?
ответ: fetchone() забирает из ответа базы только одну строку (в виде кортежа). Его используют, когда мы ищем что-то конкретное по id или проверяем факт существования записи.
fetchall() забирает сразу все строки (в виде списка кортежей). Его используют, когда нужно вывести весь список задач на экран.

4Почему (title,) — это кортеж, а (title) — нет?
ответ: В Python обычные круглые скобки используются для группировки выражений (например, в математике). Чтобы интерпретатор понял, что перед ним структура данных кортеж (tuple) из одного элемента, в конце обязательно должна стоять запятая.

5Что вернёт cursor.rowcount после UPDATE, если такого id нет?
ответ: Он вернёт 0, так как ни одна строка в базе данных не подошла под условие и не была изменена.

6Зачем проверять isdigit() перед int(input())?
ответ: Чтобы защитить программу от вылета (критической ошибки). Если пользователь случайно введёт буквы вместо цифры (например, "abc"), функция int() выдаст ошибку ValueError и программа закроется. Проверка isdigit() позволяет корректно отловить этот момент и вывести предупреждение.

7Как параметризованные запросы защищают от SQL-инъекции?
ответ: Благодаря знакам вопросов (?) база данных чётко разделяет сам SQL-код запроса и пользовательские данные. Любой ввод пользователя (даже вредоносные команды) воспринимается базой исключительно как обычная текстовая строка, которая просто запишется в ячейку.
