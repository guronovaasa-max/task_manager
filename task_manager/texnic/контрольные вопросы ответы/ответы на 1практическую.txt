1Что произойдёт, если убрать conn.commit() из скрипта и запустить его?
ответ: Изменения (создание таблицы) не сохранятся в файле базы данных. Метод commit() как раз даёт команду базе данных окончательно «зафиксировать» и записать все выполненные SQL-команды на диск.

2Чем отличается connection от cursor? Зачем нужны оба?
ответ: connection (соединение) — это «кабель», который физически связывает вашу программу с файлом базы данных. Он управляет подключением и транзакциями (например, делает commit или close).
cursor (курсор) — это «инструмент» внутри этого соединения, с помощью которого мы отправляем конкретные SQL-запросы (execute) и забираем результаты ответов (fetchall).
Нужны оба, так как один отвечает за саму связь, а второй — за работу с данными внутри неё.

3Почему id INTEGER PRIMARY KEY заполняется автоматически, хотя мы не передаём значение?
ответ: В SQLite, если колонка имеет тип INTEGER PRIMARY KEY, она автоматически становится автоинкрементным полем. Это встроенная логика базы данных: при создании новой строки SQLite сама смотрит на максимальный текущий id и прибавляет к нему единицу (1, 2, 3...).

4Что делает DEFAULT 'new' в определении колонки status?
ответ: Это значение по умолчанию. Если при добавлении новой задачи мы забудем или специально не укажем для неё статус, SQLite автоматически подставит в эту ячейку текст 'new' (новая задача).

5Где физически на диске лежат данные таблицы tasks?
ответ:Они лежат внутри созданного файла app.db, который находится в вашей рабочей папке проекта (C:\Users\Infinix\Desktop\texnic). SQLite — это встроенная база данных, поэтому вся структура и все данные хранятся прямо в этом одном файле.
